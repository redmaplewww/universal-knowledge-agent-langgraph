# 人工补证与中文一致性修复报告

日期：2026-08-11
版本：`0.3.1`

## 问题与根因

开放 Knowledge Gap 原本只有检索动作，没有能对准具体 Gap 提交人工证据的入口。用户即使知道
答案，也只能重新走普通摄取，让系统依赖关键词猜测关联，既不直观也无法保证关闭目标正确。

英文缺口来自两类原因：预览状态中存在早期英文演示材料；同时真实 Provider 的系统提示和搜索
上下文包含英文，旧合同没有把“来源语言”定义为结构化输出约束。模型因此可能在中文来源下生成
英文问题或原因。历史演示数据与本次中文对话不是同一条输入链路。

## 修复后的合同

- 每个开放 Gap 卡片提供内联“手工补证”，提交原始事实和可选来源说明。
- `POST /v1/knowledge-gaps/{gap_id}/supplements` 与 SDK 都把精确 Gap ID 注入理解上下文。
- 证据不足时保留相同 Gap 并追加 revision；足够时生成带 `resolves_gap_ids` 的候选。
- 人工补证不能跳过审批。拒绝不关闭，只有批准激活后精确关闭目标 Gap。
- 中文来源要求所有模型生成的自然语言字段保持简体中文；产品代码、ID、URL、数字、专有名词和
  原文术语保留原样。
- 首次返回发生明显英文漂移时执行一次受限结构化语言修复；仍不合格则失败关闭。
- 预览中的早期英文演示 Gap 已通过追加 revision 本地化，研究记录和未解决状态均保留。

## 真实模型验证

受管 `glm-5.2` 通过真实 HTTP 边界执行
`scripts/run_manual_gap_language_smoke.py`。中文模糊记录先正确拒答并生成中文 Gap；随后人工提交
设备手册证据，模型生成中文审批候选且 `resolves_gap_ids` 精确指向原 Gap；批准后开放 Gap 数为 0。

该验证证明的是指定旅程、指定模型配置和本地状态下的真实结果，不代表所有领域的数学穷举或
领域专家认证。生产使用仍需外部 IAM、来源可信度策略、容量和审计 Gate。
