# Universal Knowledge Agent：一个敢说不知道的知识沉淀系统

很多人把 AI 当作“很会聊天”的助手，但它并不天然适合管知识。你把资料扔给它，它可能编出一份看似合理的总结；下次再问，答案可能变了；资料越堆越多，它也说不清哪句话来自哪份文件。真实资料里也常有边界：有些结论只有在特定条件下成立，有些问题在现有材料里就是没有答案。

Universal Knowledge Agent 换了个思路：**先保存证据，再做理解；证据不够就拒答，拒答后留下缺口等待补证。**

它是一个独立的 LangGraph 项目，单机可用，SQLite 存储全部知识、证据和审批记录。输入可以是一段文档、一批测试知识，或者人工补充的一条事实。产出是一个可审计的知识库，而不是一次性的聊天记录。

## 它解决的问题

普通 RAG 的流程是“切片、向量化、检索、拼接”。它解决“找不到资料”的问题，但不保证模型理解知识，也不处理三个更麻烦的问题：

1. 模型把不同的信息混在一起。
2. 错误结论没有版本和审批记录。
3. 证据不足时继续硬答。

这个项目的答案分三层：

1. 原文先进入不可变的证据层，带内容哈希、来源和位置。
2. LLM 读整篇材料，归纳出一条自包含经验，写清背景、机制、行动、边界和依据。
3. 证据闸门判断这段理解是否被原文支持；不够就拒答，并保存知识缺口。

它的差别在于把知识处理分成证据、理解、边界三个阶段，每一步都能检查。

## 一条知识怎么被沉淀

模型读完材料后归纳成一条 Experience，字段包括：

| 字段 | 通俗解释 |
|---|---|
| title | 这条知识讲什么 |
| context | 什么场景下适用 |
| problem | 解决什么问题 |
| mechanism | 背后的原理 |
| action | 可以怎么用 |
| outcome | 期望产生什么效果 |
| rationale | 为什么这个结论成立 |
| caveats | 什么情况下不能这么用 |
| source_excerpts | 原文摘录和位置 |
| logical_relations | 因果、条件、顺序、对比等关系 |

原文会先保存为 Evidence，带内容哈希、来源和精确位置。这条经验是模型理解后的产物，不是原文的替代品。要检查模型有没有误读，就回到 Evidence 层对原文、摘录和哈希。

## 版本、审批和可审计性

知识不是一次写入就固定不变。修正会产生新 revision，旧版本保留。谁批准的、基于哪些证据、为什么这么改，都有账本可查。

高风险、低置信度、边界不清的内容不会自动上线。系统暂停在审批节点，展示模型理解、原文摘录、适用范围、风险等级、逻辑关系和待关闭缺口。审批通过后，知识进入活跃库；拒绝则保留候选但不激活。

每条知识都有适用范围，包括领域、任务、前提条件、排除项、有效期、风险等级和网络地理范围。检索时同时检查这些边界，不是所有内容都能进入同一个答案。

## 敢说不知道：知识缺口怎么工作

如果模型读完材料、检查现有知识、做有限网络搜索后仍然不能可靠理解，它不会编一个答案，而是返回 `abstained`，并生成一条知识缺口。缺口保存四个关键信息：

```json
{
  "question": "词根词缀组合成词，是否意味着所有词都含词缀？",
  "reason_unresolved": "材料只说组合方式，没说明是否存在纯词根词",
  "possible_directions": ["考察单纯词与派生词的区分"],
  "missing_evidence": ["单纯词、派生词、复合词的构成差异说明"],
  "linking_keys": ["词根", "词缀", "词"]
}
```

问题、方向、缺失证据和关键词一起保存。后续材料入库时，缺口会作为上下文交给模型；新知识可以通过 `resolves_gap_ids` 精确关闭对应缺口。人工补证走同一套流程：提供事实，系统尝试理解，审批通过后自动关联。“不知道”会变成一条等待补证的路标。

## 任意领域怎么分类和交叉

系统不预设领域词典，但用受控分类表把 LLM 识别出的领域映射到标准 ID，比如 `mathematics`、`software_engineering`、`linguistics`。一条跨学科知识可以带多个领域标签，例如句法歧义同时标 `linguistics` 和 `software_engineering`，隐私合规同时标 `legal` 和 `software_engineering`。

这些多领域标签让学科交叉自然浮现，不需要人工维护知识图谱。

### 165 条跨领域测试

这里的指标都来自 2026-09-17 的批量测试，模型为 deepseek-v4.1-flash。数据集包含 141 条单学科知识和 24 条跨学科知识，覆盖数学、物理、化学、生物、医学、语言、法律、软件工程、农业、艺术等 20 多个领域。

| 阶段 | 指标 | 结果 |
|---|---|---|
| 入库 | 总输入 | 165 |
| 入库 | active | 91 |
| 入库 | abstained | 71 |
| 入库 | failed | 3 |
| 入库 | 单学科分类准确率 | 96.55% |
| 检索 | 回答率 | 165/165 |
| 检索 | 期望学科命中 | 91.52% |
| 检索 | 单学科命中 | 127/141 |
| 检索 | 跨学科命中 | 24/24 |
| 检索 | 跨学科全覆盖 | 16/24 |

71 条拒答不是失败。整个入库过程共留下 215 个开放缺口，其中一部分来自已入库条目中尚未解释完的子问题；每个缺口都保存问题、可能方向、缺失证据和后续关联关键词。3 条失败是服务端记录问题，不是分类失败。

检索阶段又用同一批标题回查 165 次。回答率 100%，期望学科命中率 91.52%；141 条单学科命中 127 条；24 条跨学科全部命中，其中 16 条覆盖全部期望领域。14 条未命中主要因为对应输入在入库阶段拒答，检索库中没有活跃条目，不是查询失败。

## 典型场景

| 场景 | 能做什么 |
|---|---|
| 企业知识库 | 手册、运维经验、安全策略和客户案例入库，答案带出处 |
| 研究笔记 | 精读笔记、实验记录和跨学科灵感可追溯、可交叉检索 |
| 个人知识管理 | 读书笔记和项目复盘能保留边界，不把暂定判断当结论 |
| 团队协作 | 培训材料、最佳实践和踩坑记录有审批和版本账本 |
| 合规审计 | 高风险内容有人工门禁，回答能查到原文、哈希和位置 |

## 技术路线

```
输入材料
  ↓
不可变证据层（Evidence + 哈希 + 来源 + 位置）
  ↓
LLM 整篇理解（背景/问题/机制/行动/结果/依据/边界/逻辑链）
  ↓
证据闸门（支持度/摘录完整性/未知边界检查）
  ↓
证据足够 → 审批 → 版本化知识库
证据不够 → 拒答 → 知识缺口 → 人工补证或后续材料
  ↓
受控检索（领域/风险/时效/冲突/证据完整性）
  ↓
带出处的回答（经验 + 原文摘录 + 哈希 + 位置）
```

底层是 Python 3.11+、LangGraph 1.2.10、SQLite + FTS5、FastAPI。LLM 走 OpenAI-compatible 接口，不绑定云厂商。中文检索用了两层处理：索引时把 CJK 文本拆成单字加重叠 bigram，查询时同样拆分并用 OR 联合召回，由 BM25 排序控制相关度。

## 谁适合用它

如果只需要“在大量文档里找片段”，普通 RAG 更轻。这个项目适合另一类需求：材料里有机制和条件，后续会被多次询问、修正和审计；宁可暂时没有答案，也不能让未证实内容进入活跃库；希望拒答项变成可管理的缺口，而不是丢弃的失败记录。

## 快速开始

```powershell
git clone https://github.com/redmaplewww/universal-knowledge-agent-langgraph.git
cd universal-knowledge-agent-langgraph
uv sync --dev
uv run uka-lg --project-root . init
uv run uka-lg --project-root . serve --host 127.0.0.1 --port 8877
```

配置 LLM Key 后运行 `doctor --connect` 验证连接。详细用法见 [README.md](../README.md) 和 [USER_MANUAL.md](USER_MANUAL.md)。
